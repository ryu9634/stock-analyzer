# Quality Screener

미국 상장기업 전체를 재무 기반으로 매일 분석해 **투자 매력도 순위**를 웹 대시보드로 발행합니다.
GitHub Actions로 실행되고 GitHub Pages로 배포되어 서버 없이 무료로 운영됩니다.

> 단기 매매 신호를 찾는 도구가 아닙니다.
> **좋은 기업을 합리적인 가격에** 찾는 것이 목적입니다.

## 점수 체계

퀄리티 중심 혼합 방식. 각 항목은 0~100점으로 환산한 뒤 가중 평균합니다.

| 카테고리 | 비중 | 지표 |
|---|---|---|
| 수익성 | **35%** | ROE, ROIC, 영업이익률, 순이익률, 총마진 |
| 재무건전성 | **25%** | 부채비율, 유동비율, 순부채/EBITDA, FCF마진, 현금비중 |
| 성장성 | **25%** | 매출성장률, 이익성장률, 분기 이익성장, 1년 주가추세 |
| 밸류에이션 | **15%** | PER, PBR, PEG, EV/EBITDA, FCF수익률 |

### 등급

| 등급 | 점수 | | 등급 | 점수 |
|---|---|---|---|---|
| A+ | 80 이상 | | B | 56 이상 |
| A | 72 이상 | | C | 45 이상 |
| B+ | 64 이상 | | D | 45 미만 |

`—` 는 재무 데이터 커버리지가 55% 미만이어서 등급을 부여하지 않은 기업입니다.

## 설계 원칙

이 네 가지가 점수의 신뢰도를 결정합니다.

**1. 섹터 상대 평가**
PER 15는 유틸리티에서는 비싸고 반도체에서는 쌉니다. 밸류에이션 지표는 섹터 중위값
대비로 환산합니다. 표본이 8개 미만인 섹터는 비교하지 않습니다.

**2. 가중치 재정규화**
은행은 유동비율이 없고 REIT는 ROE가 구조적으로 낮습니다. 측정 불가 지표에 임의의
중간값을 주면 없는 정보를 꾸며내는 것이므로, 해당 지표를 가중치에서 제외하고
나머지로 재정규화합니다. 그래서 은행의 재무건전성은 `평가불가`로 표시될 수 있습니다.

**3. '데이터 없음'과 '나쁨'의 구분**
적자라서 PER이 없는 것은 결측이 아니라 악재입니다. 전자는 감점하고 후자는 제외합니다.

**4. 일회성 이익 교차검증**
TTM 단일 시점 지표는 자산매각·세금환입 같은 비영업 이익에 쉽게 속습니다.
순이익률이 영업이익률을 크게 웃돌면 영업이익률 기준으로 점수를 제한하고
`⚠️ 일회성 이익 의심`을 표시합니다. 매출성장률 200% 초과는 기저효과로 간주합니다.

## 분석 대상

Nasdaq 스크리너에서 미국 전체 상장물(약 7,000개)을 받아 다음을 제외합니다.

- ETF·펀드·신탁·SPAC·워런트·우선주 등 기업이 아닌 상장물
- 주가 $1 미만 — 재무 수치가 노이즈가 됩니다
- 일 거래대금 $200,000 미만 — 실제 진입·청산이 불가능합니다

시가총액 제한은 없습니다. 약 3,700개 기업이 분석 대상이 됩니다.

## 구성

```
analyzer.py                    분석 엔진
test_scoring.py                점수 함수 회귀 테스트
summary_stat.py                분석 결과 요약값 조회 (워크플로우 가드용)
index.html                     대시보드
data/analysis.js               분석 결과 (대시보드가 읽는 유일한 파일)
.github/workflows/analyze.yml  매일 자동 분석 + 배포
.github/workflows/deploy.yml   대시보드만 재배포
.github/workflows/ci.yml       PR/푸시 시 테스트
```

## 실행

```bash
pip install -r requirements.txt
```

```bash
python analyzer.py
```

점수 함수를 수정했다면 회귀 테스트를 먼저 돌리세요. 네트워크 호출 없이 1초 안에 끝납니다.

```bash
python test_scoring.py
```

전체 스캔은 약 8~12분 걸립니다 (가격 데이터 + 재무 데이터 병렬 수집).
`data/analysis.js` 가 생성되면 `index.html` 을 브라우저로 열면 됩니다.

재무 데이터는 `data/.fundamentals_cache.json` 에 20시간 캐시됩니다. 이 파일은
커밋되지 않으므로 로컬 반복 실행만 빨라지고 저장소는 비대해지지 않습니다.

## 설정

주요 상수는 `analyzer.py` 상단에 있습니다.

| 상수 | 기본값 | 설명 |
|---|---|---|
| `MIN_PRICE` | `1.0` | 최소 주가 |
| `MIN_DOLLAR_VOLUME` | `200_000` | 최소 일 거래대금 |
| `INFO_WORKERS` | `14` | 재무 조회 동시 요청 수 |
| `MIN_COVERAGE` | `0.55` | 등급 부여 최소 데이터 커버리지 |
| `FULL_DETAIL_TOP` | `400` | 상세 지표를 저장할 상위 기업 수 |
| `CATEGORY_WEIGHTS` | — | 카테고리 비중 |

가치투자 성향을 강화하려면 `CATEGORY_WEIGHTS` 에서 `valuation` 비중을 올리고
`growth` 를 낮추면 됩니다.

## GitHub Pages 배포

1. Settings → Pages → Source: **GitHub Actions**
2. Settings → Actions → General → Workflow permissions: **Read and write**
3. Actions 탭에서 `기업 분석 & 대시보드 배포` → Run workflow

이후 매일 한국시간 아침 7시 43분(평일)에 자동 실행됩니다. 재무 데이터는 분기
실적 발표 때만 바뀌므로 하루 1회로 충분합니다.

## API 레이트리밋

yfinance는 Yahoo Finance의 비공식 엔드포인트를 씁니다. 재무 데이터를 연속으로
대량 조회하면 중간부터 스로틀이 걸립니다(초당 24건 → 4건, `Invalid Crumb` 401).
이에 대응해 다음을 두었습니다.

- 동시 요청 8개로 제한하고, 스로틀 신호(429/401)를 만나면 6초부터 지수 백오프
- 재무 데이터를 72시간 캐시 — Actions 캐시로 유지되어 매 실행이 따뜻하게 시작
- 조회 예산 15분 초과 시 중단하고 수집된 분량으로 진행
- 수집 커버리지가 70% 미만이면 경고 출력
- **데이터 회귀 가드** — 등급부여 기업이 직전 대비 40% 넘게 줄면 워크플로우가
  실패하고 기존 데이터를 유지합니다. 수집에 실패한 빈약한 결과가 멀쩡한
  데이터를 덮어쓰지 않습니다

짧은 시간에 여러 번 전체 스캔을 돌리면 스로틀에 걸립니다. 캐시가 남아 있으므로
잠시 후 다시 실행하면 누락분만 채웁니다.

## 한계

- **데이터 출처의 한계** — yfinance의 TTM 지표를 사용합니다. 일회성 이익 가드를
  두었지만 원천 데이터 자체의 오류는 걸러낼 수 없습니다. 상위 종목은 실제
  재무제표로 교차 확인하시기 바랍니다.
- **다년 추세 부재** — 지표 일관성(5년 ROE 추이 등)은 종목당 추가 API 호출이
  필요해 포함하지 않았습니다. 성장의 질보다 성장의 크기를 봅니다.
- **정성 평가 부재** — 경영진, 경쟁우위, 규제 환경은 숫자에 담기지 않습니다.

## 면책

투자 참고자료이며 수익을 보장하지 않습니다. 점수가 높다고 매수 신호가 아닙니다.
투자 판단과 그 결과에 대한 책임은 본인에게 있습니다.
